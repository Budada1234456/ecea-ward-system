# 三人协作任务：表单字段、Word 编辑与 PDF 输出升级

## 目标与边界

三位协作者并行完成网页字段、富文本与 Word 导入、PDF 表格和签章终稿流程。通过独立目录和独立分支减少冲突，由 A 统一修改现有共享入口文件。

本轮必须保持现有 PDF 上传、分块、OCR、字段识别和导入行为不变，不为超大 PDF 另行改造识别能力。

## 统一验收口径

- 网页表单、保存数据、Word 字段映射、预览和 PDF 使用同一套字段名称、顺序和内容。
- 奖项、知识产权、论文著作、应用单位、经济效益、合作记录、主要完成人和主要完成单位均在网页端以结构化字段编辑，并在 PDF 中输出对应表格。
- 主要完成人和主要完成单位填写后均可排序，保存顺序、显示名次和 PDF 顺序一致。
- 每名完成人和每个完成单位分别生成一页 A4 表格页。
- 长文本支持限定的字体、字号、粗细、对齐、列表、链接和图片格式；编辑器缩放不改变保存内容和导出结果。
- Word 导入必须先展示候选变更，用户确认后才写入；首期支持 .docx，旧版 .doc 暂缓。
- 签章前版本、识别源文件、推荐书附件和已签终稿是不同文件角色，不能互相覆盖或送入错误的识别流程。

## 学科分类口径

> 学科分类：按照国家学科分类标准（与国家科学技术奖励学科分类口径一致），以项目主要技术方向为依据，最多可选择 3 项，按与项目内容的紧密程度排序。填写的第一项学科默认为所属科学技术领域。

- 数据源必须来自政府或国家科学技术奖励的权威分类文件，不得用某协会自有分类代替。
- B 在录入数据前记录分类来源、发布机构、版本或生效日期、代码层级和复核人。
- 下拉控件支持按官方代码或中文名称搜索，最多选择 3 项，禁止重复。
- 已选项目以 1–3 编号显示，支持上移、下移和删除。
- 第一项变化后，“所属科学技术领域”只读值立即同步变化。
- 保存为有顺序的 code/name 数组；网页、Word 映射、预览和 PDF 使用同一顺序。
- 旧版自由文本值保留为“待确认”，用户替换前不得静默映射或删除。

## A：富文本、Word 导入与最终集成

- 分支：feature/editor-word
- 独占工作区：src/editor/、src/import/、lib/word-fields.mjs、routes/word-import.mjs
- 独占测试：tests/fixtures/synthetic-import.docx、tests/rich-text-word.e2e.spec.js
- 共享文件唯一修改人：src/main.jsx、src/styles.css、server.mjs、package.json、package-lock.json、README.md、tests/e2e.spec.js

### A 的详细任务

1. 把现有长文本编辑器拆入 src/editor/，支持限定字体、字号、粗体、对齐、列表、链接和图片，保证保存、重载、预览及导出一致。
2. 实现会话级视图缩放：默认 100%，范围 70%–150%，每次 10%，提供当前倍率和复位；仅编辑器获得焦点时响应 Ctrl/Cmd + 滚轮，倍率不写入数据。
3. 在右上角增加 .docx 导入入口，解析标题、段落和表格后生成候选字段，沿用现有 PDF 导入的“先审阅、后应用”方式。
4. 导入界面覆盖文件选择、解析中、失败、无匹配、部分匹配、候选审阅、应用中、应用失败和成功状态。
5. 候选项显示现值、建议值、来源、置信度和冲突状态；非空字段默认不覆盖，重复记录追加并去重，取消或失败不得改变原草稿。
6. 对粘贴内容、导入内容和服务器保存内容执行一致的标签、属性、CSS 属性和 URL 协议白名单校验。
7. 拒绝宏、加密文件、外部关系、异常压缩包和超限文档，并清理临时文件；不修改原有 PDF 识别路由。
8. 为 A 修改的每个长文本编辑区和 Word 导入区域补充就近填写指引。指引中的章节用途、填写内容、字数限制、格式和图片要求以官方 Word 申报模板为准；指引不得保存、导入覆盖或导出为申报正文。
9. B、C 合并后，由 A 统一接入共享入口、依赖、服务器挂载和最终回归。

### A 的验收

- Word/WPS 粘贴和 .docx 导入后，受支持格式能够保存、重载、预览和导出。
- 只应用部分候选字段时，未选择字段和已有非空数据保持不变。
- 缩放不改变保存的 HTML 或 PDF 字体。
- 每个修改区域都能看到与 Word 模板对应的填写指引，且指引不进入申报数据。
- 恶意、超限或不支持的文档不会改变草稿，不残留临时文件。
- 原有 PDF 识别测试全部通过。

## B：网页字段、学科分类与人员/单位排序

- 分支：feature/form-fields
- 独占工作区：src/forms/、src/data/disciplines.js、src/schema/table-fields.js、src/utils/reorder.js
- 独占测试：tests/forms-ordering.e2e.spec.js
- 不得修改：A 管理的共享入口文件和 C 的导出目录

### B 的详细任务

1. 将网页字段定义集中到 src/schema/table-fields.js，统一字段键、标签、类型、列宽、必填状态、显示顺序和 PDF 可见性。
2. 完成奖项、知识产权、论文著作、应用单位、经济效益、合作记录、主要完成人和主要完成单位的网页结构化表格。
3. 实现国家学科分类分级搜索选择器，严格落实本 Issue 的“学科分类口径”。
4. 主要完成人、主要完成单位和学科分类均提供拖动、上移、下移操作；触控目标至少 44×44 CSS 像素，首尾无效操作禁用，移动后焦点保持并播报名次。
5. 人员和单位采用“摘要列表 + 单条详情”方式：新增后自动选中；切换时保留校验错误；删除需确认；删除后定位相邻记录；移动端返回列表时恢复焦点和滚动位置。
6. 桌面端显示完整表格；窄屏仅允许表格容器内部横向滚动，页面本身不横向溢出，识别列和操作列保持可见。
7. 保持旧 JSON 字段可读；旧学科自由文本保留为“待确认”。
8. 为 B 修改的每个网页表单、结构化表格和学科选择区域补充就近填写指引。字段含义、必填状态、长度限制、填写口径和示例以官方 Word 申报模板为准，不另做脱离字段的总帮助页。

### B 的验收

- 每类表格均可新增、编辑、删除并正确自动保存。
- 人员、单位和学科在鼠标、触控和纯键盘操作下均能排序，刷新后名次不变。
- 可按学科代码和中文名称搜索，重复项和第 4 项被阻止。
- 第一学科变更后，保存数据、只读领域、预览和 PDF 使用同一派生结果。
- 最窄目标视口没有页面级横向溢出。
- 每个修改区域的填写指引与 Word 模板对应，且不会遮挡或挤压输入控件。
- B 先提交并合并字段 Schema，供 C 使用。

## C：PDF 表格、单人/单单位页和签章终稿

- 分支：feature/pdf-output
- 独占工作区：src/export/、lib/signed-final-files.mjs、routes/signed-final.mjs
- 独占测试：tests/pdf-export.e2e.spec.js
- 依赖：B 的 src/schema/table-fields.js 合并后再完成字段模板

### C 的详细任务

1. 预览使用语义化 HTML 表格；PDF 表格使用 jsPDF 文本/表格能力和可再分发的嵌入式中文字体，中文表头和单元格内容必须可检索、可选择。
2. 所有网页结构化表格在预览和 PDF 中保持相同标签、列顺序、行顺序、值和空值规则。
3. 表格分页不得截断记录；跨页重复表头；PDF 结果不能依赖当前浏览器窗口宽度。
4. 按保存名次为每名完成人和每个完成单位分别生成完整 A4 表格页。
5. 根据正式 Word 模板核对签字、盖章页面的内容、顺序和最终位置，再生成完整签章前版本。
6. 建立独立终稿模块：识别源只读；签章前版本可重新生成和下载；已签终稿可上传、下载和确认替换。
7. 已签终稿仅接受校验通过的 PDF，记录哈希、上传人和时间。新文件原子化成为“当前版本”，旧文件及审计记录保留且受权限保护。
8. 客户端不能自行指定文件角色；跨项目访问、角色伪造及未授权替换必须由服务器拒绝。

### C 的验收

- 填满所有网页表格后，预览和 PDF 的字段、值与顺序逐项一致。
- PDF 文本提取能找到中文表头和单元格内容，不能只是整页截图。
- 多页表格不截行、不漏行，并重复表头。
- 人员和单位排序变化后，单页输出顺序同步变化。
- 签章页位于正式模板要求的位置。
- 已签终稿下载内容与原文件字节一致，替换后只有新文件标记为当前，识别源保持不变。
- 跨用户、跨项目和伪造角色测试均被拒绝。

## 协作与同步方法

1. 三人从最新 main 创建各自指定分支，只修改本 Issue 分配的独占工作区。
2. 每次开始工作先同步 origin/main，再把本人的功能分支变基到最新主线。
3. 尽早创建 Draft PR；PR 写明字段变化、接入点、截图、保存数据验证和 PDF/预览验证。
4. 合并顺序：B 的 Schema/网页表单 → C 的 PDF/签章模块 → A 的编辑器/Word 和共享文件集成。
5. B 合并后 C 更新主线；B、C 合并后 A 更新主线并完成共享接线。
6. 文件冲突由文件负责人解决，禁止用旧版整个覆盖 src/main.jsx 或 src/styles.css。
7. main 建议开启分支保护：必须 PR、至少一人审核、测试通过，禁止协作者直接推送。
8. 禁止提交 data/、数据库、密码、Cloudflare 凭据、用户上传文件和真实申报材料。测试只使用合成数据。
9. GitHub 合并只同步源代码，不会自动部署。最终由 A 在运行电脑上备份、拉取、构建、回归并重启服务。

## 暂不实施

- 超大 PDF 识别优化，以及任何现有 PDF OCR/字段识别逻辑调整。
- 多人同时编辑同一份申报数据、在线冲突合并和字段锁。
- SQLite 迁移和对象存储迁移。
- 首期旧版二进制 .doc 解析。
- 任意 Word 样式的像素级完全还原。
